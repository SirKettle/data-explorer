## Colours

Anywhere a colour is accepted (an item's `color`, the palette, a background, an edge style) you can
pass a `0xRRGGBB` number or a CSS string: `#rrggbb`, `#rgb`, `rgb()`/`rgba()` or
`hsl()`/`hsla()`, with commas or spaces. Alpha is ignored, because the explorer sets transparency
per layer. Named colours (`"tomato"`) are not supported, and a value that does not parse is ignored
as if it had not been set (`parseColour`, in `./headless`, checks one yourself).

An item's own `color` wins over its `ramp` position, which wins over the stable per-id colour. A
hollow aggregate keeps the palette's `aggregate` colour, so it never looks like an item.

## Backgrounds

`background` is drawn in layers, bottom to top: `color`, then `gradient` (`{ from, to, angle? }`,
with `angle` in degrees as in CSS), then `image`, then the dot `grid`. Leave it out and you get the
palette's background with the grid. Like every option, it is live: pass a new value and the canvas
redraws, with no new scene and no camera reset, and values are compared by content, so an inline
object costs nothing on re-render.

| Option | Default | Effect |
| --- | --- | --- |
| `background.color` | `palette.background` | A solid colour behind everything. |
| `background.gradient` | none | `{ from, to, angle? }`: 180 (the default) runs top to bottom, 90 left to right. |
| `background.image` | none | A URL, or `{ url, fit?: "cover" \| "tile", alpha? }`, fixed to the view. It needs [CORS](/data-explorer/guides/images-and-cors/). |
| `background.grid` | on (alpha 0.22, `palette.grid`) | `false` hides it; `{ alpha, color, step, zoom, minScreenStep, tile }` restyles it. See below. |

### Your own grid

The grid is anchored to the world, so it pans and zooms with the scene. `step` is the world distance
between repeats (160 by default). `zoom: "snap"` (the default) keeps the spacing between 36 and 190 px
by stepping it by 4× as you zoom; `zoom: "continuous"` keeps `step` fixed, so the pattern scales
smoothly like a baseplate, and fades out once it is under `minScreenStep` px (8 by default).

To replace the dots, give `tile` a lazy import, the way you give `renderers`. The module draws one
repeating tile from the PixiJS classes in `kit`, in white or greys: `color` tints it and `alpha` fades
it. It is drawn once, at 2× resolution.

```ts
// stud-tile.ts
import { defineGridTile } from "@thirkettle/data-explorer/pixi";

export default defineGridTile({
  size: 64,
  draw(kit) {
    const tile = new kit.Container();
    tile.addChild(new kit.Graphics().circle(32, 32, 14).fill(0xffffff).stroke({ width: 2, color: 0x808080 }));
    return tile;
  },
});

// <DataExplorer background={{ grid: { tile: () => import("./stud-tile"), step: 80, zoom: "continuous" } }} />
```

Pass the same function each render (a module-level constant, or an inline `import()` arrow you keep
stable), because a new function reloads the tile. If it fails to load or draw, the dots are used.
